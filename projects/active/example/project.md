# 低成本高性能存储方案选型

## 项目目标

在单节点成本 ≤ 5000 元的约束下，搭建一套兼顾高性能（4K 随机读 ≥ 500K IOPS）和大容量（≥ 40TB）的存储方案，用于本地 AI 训练数据集的存取。

## 背景

AI 训练数据集规模快速增长（单数据集 10TB+），同时训练任务对随机读性能要求较高。传统 HDD 阵列（RAID 10）虽成本低但 IOPS 严重不足，全闪存方案性能好但超出预算。

## 方案对比

| 方案 | 配置 | 估算成本 | IOPS（4K 随机读） | 容量 |
|------|------|----------|-------------------|------|
| 纯 HDD | 8×10TB HDD RAID 10 | ¥3200 | ∼5K | 40TB |
| 纯 SSD | 4×8TB NVMe SSD RAID 5 | ¥8000 | ∼800K | 32TB |
| 混合方案 | 2×4TB NVMe SSD + 5×10TB HDD | ¥4800 | ∼500K (缓存命中) | 46TB |

## 推荐方案：混合存储（bcache + ZFS）

### 架构设计

```
┌──────────────────────────────────┐
│         应用层（训练框架）         │
└──────────────┬───────────────────┘
               │
┌──────────────▼───────────────────┐
│         ZFS zpool                │
│  ┌──────────┐  ┌──────────────┐  │
│  │ NVMe SSD │  │  HDD 阵列    │  │
│  │ (bcache) │  │  (RAID-Z2)   │  │
│  └──────────┘  └──────────────┘  │
└──────────────────────────────────┘
```

### 关键决策

- **ZFS over Btrfs**：参考 [[software/zfs.md]]，ZFS 的 CoW 快照和校验能力成熟度更高
- **bcache 作为读写缓存**：利用 [[concepts/lsm-tree.md]] 的写入优化思想，热点数据驻留 NVMe SSD
- **RAID-Z2**：允许双盘故障，容忍 10TB 大容量盘的重建风险

### 风险与缓解

- **写放大**：[[concepts/write-amplification.md]] 指出 ZFS CoW + bcache 可能引入双重写放大，需预留 20% OP
- **SSD 寿命**：[[concepts/wear-leveling.md]] 建议选择 TBW ≥ 3× 预期写入量的 SSD

## 决策记录（ADR）

### ADR-001：选择 ZFS 而非 Btrfs

- **状态**：已采纳
- **理由**：ZFS 社区成熟，CoW 实现更稳定，RAID-Z 相比于 Btrfs RAID 5/6 的 write hole 问题更可靠
- **参考**：[[software/zfs.md]]

### ADR-002：使用 bcache 实现 SSD 缓存

- **状态**：已采纳
- **理由**：内核原生支持，与 ZFS 配合良好，避免将全部数据放置在昂贵的 NVMe SSD 上
- **参考**：[[concepts/lsm-tree.md]] 的热冷分离思想
