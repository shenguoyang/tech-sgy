# 费曼学习法操作手册

> 这不是一个普通的知识库目录。这是你**用「教」来学**的地方。
> 每一门课程都驱动你发现理解中的盲点。

---

## 操作流程

### 步骤 1：选一个问题

翻开 [[projects/active/windows高性能存储方案/requirements.md]]，看哪个需求让你觉得「这个我不太清楚」。或者看 [[_index|knowledge-graph.md]] 中哪个概念还没学。

**好的问题**（以项目问题驱动）：
- 「为什么 NTFS 在大量小文件下会卡顿？」→ 关联 R1, R5
- 「CoW 如何保证数据不丢失？」→ 关联 R3
- 「写放大到底是怎么产生的，怎么量化？」→ 关联 R4, R10

**问题 → 粒度**：
- 一个具体问题 → **微课程（micro）**
- 一组关联概念的系统理解 → **章节式课程（chapter）**

### 步骤 2：生成教学草稿

对我（AI）说：
> 「教我 CoW 在本项目中的具体应用」

我会读取 wiki/ 相关知识，生成一篇教学笔记写到 `courses/drafts/`。它以「教一个初级工程师」为目标读者，包含类比、核心机制、Windows 实现、项目影响分析。

### 步骤 3：审阅并触发对打

你读完草稿后，说：
> 「对打」

我会扮演对该领域**不太了解但有技术直觉的工程师**，逐段提问：
- 「这个类比我能不能用一个更简单的？」
- 「为什么这里要这样？有没有不用 xxx 也能解释的方式？」
- 「这两个机制看起来矛盾，你确定他们不冲突？」

对打提炼的要点我自动保存到 `courses/_battles/`。

### 步骤 4：完善并发布

根据对打中发现的盲点，你（或我辅助）修改草稿。满意后标记为 `published`。

```
└── published/           ← 已审阅发布的可分享教程
```

## 费曼自检清单

每篇教学笔记完成后，检查：

- [ ] **一句话测试**：能用一句话说清楚核心思想吗？
- [ ] **祖母测试**：去掉所有术语，一个门外汉能大致听懂吗？
- [ ] **类比完备**：至少有一个日常类比，且知道类比失效的边界在哪里
- [ ] **项目映射**：知道这个概念在本项目的哪个场景、哪条需求中落地
- [ ] **回查确认**：对打中发现的盲点是否已澄清并补充进笔记
- [ ] **链接完整**：页面内至少含 2 个指向 wiki/ 或 projects/ 的内部链接

## 对打提示词速查

| 你想做什么 | 对我说 |
|-----------|--------|
| 生成教学草稿 | 「教我 xxx」「用费曼法解释 xxx」 |
| 触发对打 | 「对打」「挑战我」「提问模式」「socratic」 |
| 优化类比 | 「这个类比好不好？」「有没有更好的类比？」 |
| 发现盲点 | 「我哪里没讲清楚？」「漏洞在哪里？」 |
| 检查完整性 | 「我的自检清单还有哪些没通过？」 |

## 和知识库其他层的关系

```
raw/ ──→ wiki/ ──→ courses/drafts/ ──对打──→ courses/published/
                                  ↑                    │
                                  │                 知识回流
                                  │                    ↓
                                  ←────── wiki/ (更新/补充)
```

- **raw/** → 对打中发现知识盲点，回查 raw/ 资料补充
- **wiki/** → 教学笔记的深度知识来源
- **projects/** → 教学选题的驱动来源
- **assets/** → 教学笔记中的图片/动画/交互组件
